# ギリギリ・ナンバー Web Edition

4〜16人で遊べる、教員進行型・数字の心理戦ゲームです。GitHub Pages で公開できる静的Webサイトで、**複数端末のリアルタイム同期には Firebase Realtime Database と匿名認証**を利用します。

## 1. まずはデモを試す

`firebase-config.js` を未設定のまま、ローカルのHTTPサーバーか GitHub Pages で `index.html` を開くと **DEMO** と表示されます。教員用ルームを作ると架空の生徒6人が入った状態になるので、ゲーム開始→「デモ生徒の数字を自動提出」→締切→順番に発表→結果という一連の流れを試せます。

> **重要：** デモはそのブラウザの `localStorage` のみを利用します。別の端末には同期しません。同じブラウザ・端末で動作確認をするための機能です。URL に `file://` を使うとブラウザによって ES モジュールの読み込みが制限されるので、原則HTTPサーバーかGitHub Pagesで閲覧してください。

PCならプロジェクトフォルダで `python3 -m http.server 8080` として、`http://localhost:8080` を開きます。

## 2. Firebase 初期設定（端末間同期に必須）

1. [Firebase コンソール](https://console.firebase.google.com/)でプロジェクトを新規作成します。
2. ウェブアプリ（`</>`）を追加します。表示される「Firebase SDK 設定」の `firebaseConfig` を控えます。
3. **Authentication → Sign-in method → 匿名**を有効にします。教員・生徒ともメールアドレスやパスワードは不要です。
4. **Realtime Database** を作成します。アジアの近いリージョンを選択します。**テストモードの公開ルールをそのまま残さない**でください。
5. Realtime Database の「ルール」タブを開き、付属の `database.rules.json` の**全文を貼り付け**て公開します。
6. ルート直下の `firebase-config.js` を編集し、`apiKey`、`authDomain`、`databaseURL`、`projectId`、`appId` の5値を実際の値に置き換えます。`databaseURL` は Realtime Database の URL です（例：`https://example-default-rtdb.asia-southeast1.firebasedatabase.app`）。
7. **Authentication → 設定 → 承認済みドメイン**に公開サイトのドメイン（例：`ユーザー名.github.io`）を追加します。ブラウザや構成により不要な場合もありますが、設定しておくと安全です。
8. サイトを再読み込みし、右上が `LIVE` になっていれば準備完了です。教員がルームを作り、別端末から8文字のルームコードで参加してください。

Firebase コンソールの「ウェブアプリ設定」は**クライアント公開用**情報です。**サービスアカウントの秘密鍵や管理者SDKの資格情報をGitHubへ絶対に置かない**でください。また、アクセス制限は `database.rules.json` 側で行います。

## 3. GitHub Pages への公開（ZIPを使う場合）

1. ZIPを解凍し、GitHubで新しいリポジトリを作成します（例：`girigiri-number`）。
2. **`index.html` と `firebase-config.js` がリポジトリのルート直下**になるように、解凍した中身をアップロードします。ZIPファイルだけをアップロードしてもサイトにはなりません。
3. GitHubのリポジトリ → **Settings → Pages → Build and deployment → Deploy from a branch** を選びます。ブランチを `main`、フォルダを `/(root)` にして保存します。
4. 公開された `https://ユーザー名.github.io/girigiri-number/` にアクセスします。
5. 教員がルームを作り、表示されたコードまたは参加URLを生徒に渡します。教員用URLは他の端末に送っても教員権限にはなりません。

GitHub Pages の公開だけでは**オンライン同期は実現できません**。必ず上のFirebase設定も行ってください。

## 4. 進行方法

- 生徒は「ルームコード → ニックネーム」で参加します。受付中に限り参加できます。教員は受付中に参加者を削除できます（16人上限）。
- 教員が上限と応用ルールを設定してゲームを始めます。設定は各ゲーム開始時に確定し、そのゲーム中は変更できません。
- 生徒は **1〜10から1つ**を選択して提出。**各生徒は5ゲームで1ラウンドの間、同じ数字を再使用できません**。次ラウンドで使用済み数字をリセットします。他の生徒と同じ数字を選ぶことは可能です。
- ディフェンスがONのときは0を選べます。0は得失点なし・何度でも使用可能です。
- 教員は提出状況を確認して締め切ります。未提出者は棄権として**そのゲームは0点**、カードは消費しません。
- M-1風の演出として、**名前発表→数字公開**の2段階で1人ずつ進めます。公開済み数字の合計が随時表示されます。全員公開後、結果を確定します。
- 基本：上限以下なら選択数がプラス得点、上限超過ならマイナス得点。
- 各ゲームの得点は大会全体に累積。**5ゲーム終了で次のラウンド**。教員の好きなタイミング（結果画面）で大会を終了できます。トップが同点の場合は同点優勝です。
- 「得点履歴をCSV保存」で1ゲームごとの結果をダウンロードできます。

## 5. 応用ルールと複数同時ON時の優先順位

| ルール | 詳細 |
|---|---|
| セーフゾーン | 上限に加えて下限を設定。**合計が下限未満**なら、正の数字を出した者のうち最小値の全員が、出された正の数字の最大値ぶんマイナス。他の人は0点。ディフェンスの0と棄権の0は最小値判定の対象外。全員0なら全員0点。 |
| ボーナス | 教員が設定した倍率（×2〜10）を得失点に掛ける。 |
| バッティング | 同じ正の数字を出した人数で、各人の基礎点を割る。小数は**0に向かって切り捨て**（例：−5÷2 → −2）。防御0は対象外。 |
| セーフ・アウト予想 | 下限未満も「アウト」。セーフ予想的中なら得点×2、セーフなのにアウト予想なら0点、アウト予想的中なら0点、アウトなのにセーフ予想ならマイナス得点×2。ディフェンスと棄権は常に0点。 |
| ディフェンス | 0を選んで得失点なし。カード消費なし。複数回可能。 |
| ダブルアップ | 生徒が **×2・×3・×4・×5** を選択（選択しない選択肢もあり）。**大会を通じて1ゲームだけ使用可能**。提出を変更した場合、締切時点の選択で消費判定。0を選んでいても倍率を使ったら権利を消費。 |

**得点計算の順番（重要）**

1. 合計を判定し「成功」「上限超過」「下限未満」の基礎点を決定。
2. バッティング（人数割り・0方向切捨て）。
3. ボーナス倍率。
4. セーフ・アウト予想の2倍／0点判定。
5. ダブルアップ倍率。

例えば「上限超過・6を3人が選択・バッティングON・ボーナス×3・セーフと誤予想・ダブルアップ×2」なら、`−6 → −2 → −6 → −12 → −24点` になります。

## 6. セキュリティと運用上の注意

- 認証はFirebaseの**匿名認証**です。教員の操作権限は「そのルームを作成した匿名ユーザーID」に紐づき、RTDBのルールで権限チェックされます。ページの表示だけで教員になれるわけではありません。
- **教員は作成した同じブラウザ・プロファイルを使う**必要があります。ブラウザデータを消すと権限を失う場合があります。学校で継続運用する場合は、Firebase Authの教師用メール/パスワード認証の追加実装を推奨します。
- ニックネーム・得点などの公開ルーム情報は、ルームコードを知る匿名認証ユーザーが閲覧できます。一方、**発表前の各自の数字は `privateSubmissions` に分離し、本人と教員以外はFirebaseのルールで読めないようにしています**。締切時に教員用の `privateLocked` に回答を保存し、1人ずつ公開します。**氏名、学籍番号などは入力させず、推測されにくい8文字コードを使いましょう**。厳密な不正防止や原子的な締切が必要な場合はCloud Functionsでサーバー側の締切と得点計算を行ってください。
- ゲーム運営に必要な最小限の情報のみ保存しますが、Firebase上のルームは**自動削除されません**。授業後はFirebaseコンソールで不要な `/rooms/コード` を削除してください。
- 実際の回線を使った多端末動作は、Firebaseプロジェクトを設定してから別のスマホ・PCで確認してください。ネットワーク障害時のオフライン自動送信保証はありません。

## 7. ファイル構成

```text
index.html                   ページ
styles.css                   レスポンシブデザイン
favicon.svg                  ロゴ
firebase-config.js           Firebaseの接続先設定（要入力）
database.rules.json          Firebase RTDBの権限ルール（要適用）
src/main.js                  画面・教員進行・生徒操作
src/engine.js                得点計算（UIと分離）
src/store.js                 Firebase/デモ通信
package.json                 テスト実行用
README.md                    この説明書
tests/engine.test.js         得点計算の自動テスト
```

テストは Node.js で `npm test` を実行できます。ZIPにnode_modulesは含めません。実行に外部パッケージのインストールは不要です。
